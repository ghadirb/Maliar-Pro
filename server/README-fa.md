# بک‌اند پرداخت مالیار پرو (زرین‌پال)

این یک سرور Node.js بسیار ساده است که سه کار را انجام می‌دهد:
1. شروع پرداخت زرین‌پال برای اشتراک ماهانه/سالانه (`POST /payment/request`)
2. دریافت بازگشت از زرین‌پال و تایید پرداخت، سپس فعال‌سازی اشتراک (`GET /payment/callback`)
3. اعلام وضعیت اشتراک به اپ اندروید (`GET /subscription/status`)

## مرحله ۱: ثبت مرچنت در زرین‌پال
1. به [zarinpal.com](https://www.zarinpal.com) بروید و ثبت‌نام کنید (نیاز به کد ملی/مدارک کسب‌وکار دارد).
2. بعد از تایید، از پنل زرین‌پال یک "Merchant ID" (یک UUID) دریافت می‌کنید.
3. برای تست، از [sandbox.zarinpal.com](https://sandbox.zarinpal.com) هم می‌توانید مرچنت آزمایشی رایگان بسازید (کارت واقعی لازم نیست).

## مرحله ۲: دیپلوی روی لیارا
از همان حساب لیارایی که برای GapGPT/AI proxy استفاده می‌کنید:

1. یک اپ جدید از نوع **Node.js** در پنل لیارا بسازید (مثلاً به نام `maliar-billing`).
2. لیارا CLI را نصب کنید: `npm install -g @liara/cli`
3. داخل پوشه‌ی `server` این دستورات را بزنید:
   ```
   liara login
   liara deploy --app maliar-billing
   ```
4. بعد از دیپلوی، آدرسی مثل `https://maliar-billing.liara.run` به شما داده می‌شود.
5. از پنل لیارا → اپ `maliar-billing` → بخش Environment Variables، مقادیر زیر را ست کنید
   (شبیه فایل `.env.example` همین پوشه):
   - `ZARINPAL_MERCHANT_ID`
   - `ZARINPAL_SANDBOX` (اول `true` برای تست، بعد `false`)
   - `PUBLIC_BASE_URL` = همان آدرسی که لیارا داد (بدون `/` انتهایی)
   - `PRICE_MONTHLY_RIAL`, `PRICE_YEARLY_RIAL` (به ریال)

### ⚠️ نکته‌ی مهم درباره‌ی db.json
این نسخه‌ی ساده، وضعیت کاربران را در یک فایل `db.json` کنار خود سرور نگه می‌دارد. اگر
اپ لیارا redeploy شود، ممکن است این فایل پاک شود. برای جلوگیری از این مشکل، از پنل
لیارا یک **Disk** بسازید و آن را به مسیر پوشه‌ی سرور متصل (mount) کنید، یا وقتی
کاربرهای واقعی و پولی زیاد شدند، این چهار تابع بالای `index.js` (`loadDb`, `saveDb`,
`getPremiumUntil`, `grantPremiumDays`) را با یک دیتابیس واقعی (مثلاً Postgres که خود
لیارا هم ارائه می‌دهد) جایگزین کنید - بقیه‌ی کد بدون تغییر کار می‌کند.

## مرحله ۳: وصل کردن اپ اندروید به این بک‌اند
فایل زیر را در پروژه‌ی اندروید باز کنید و آدرس واقعی را جایگزین کنید:

`app/src/main/java/com/maliar/pro/utils/SubscriptionManager.kt`
```kotlin
const val BACKEND_BASE_URL = "https://maliar-billing.liara.run"
```

سپس اپ را دوباره بسازید (rebuild) و نصب کنید.

## مرحله ۴: تست کامل
1. با `ZARINPAL_SANDBOX=true`، از اپ روی دکمه‌ی «اشتراک ماهانه» بزنید.
2. مرورگر باز می‌شود؛ در صفحه‌ی آزمایشی زرین‌پال هر شماره کارت آزمایشی که خودشان
   در مستنداتشان می‌دهند را وارد کنید (پرداخت واقعی انجام نمی‌شود).
3. بعد از برگشت، صفحه‌ی «پرداخت با موفقیت انجام شد» باید دیده شود.
4. به اپ برگردید؛ در صفحه‌ی «مدیریت اشتراک»، وضعیت باید «پریمیوم تا تاریخ ...» را نشان دهد.
5. وقتی مطمئن شدید همه‌چیز درست کار می‌کند، `ZARINPAL_SANDBOX` را روی `false` بگذارید
   و مرچنت واقعی (غیر sandbox) را جای `ZARINPAL_MERCHANT_ID` بگذارید.

## نکات امنیتی برای بعداً (نه ضروری برای شروع)
- الان هر کسی که deviceId یک نفر دیگر را حدس بزند می‌تواند وضعیتش را ببیند (نه تغییر
  بدهد - چون activation فقط از مسیر verify زرین‌پال اتفاق می‌افتد). برای مقیاس بزرگ‌تر،
  یک HMAC ساده روی deviceId اضافه کنید تا `/subscription/status` هم امن‌تر شود.
- اگر بعداً لاگین واقعی (شماره موبایل/ایمیل) اضافه کردید، `deviceId` را با یک شناسه‌ی
  کاربر واقعی جایگزین کنید تا با تعویض گوشی، اشتراک کاربر از دست نرود.
